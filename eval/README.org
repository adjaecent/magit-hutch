#+title: magit-hutch: eval analysis

The eval harness is a mix of strategies from [[https://github.com/withmartian/code-review-benchmark][Martian's code review]] benchmark and the [[https://arxiv.org/html/2603.11078v1][CR-Bench preprint]]. Most code review benchmarks rely on GitHub PR analysis, but since Hutch is a local-review agent inside emacs we modify the eval harness to work against locally staged or unpushed diffs. Hutch evals run emacs in a batched headless mode to capture results without running the rendering layer.

** Methodology

We take the golden comments from Martian's dataset (with the exclusion of =discourse=, since the dataset doesn't map cleanly). Hutch primarily runs as a single-shot LM (no self-improvement or reflexion agent capabilities at the moment) and computes Precision, Recall, Fβ score, Usefulness Rate and SNR (based on CR-Bench).

Due to cost reasons, Hutch's findings (across =40= PRs from the dataset) are classified by a single LLM judge (=gpt-5.2=) into: Bug hit, Validity and Noise. This has some reliability limits of single-judge variance and same-family bias. But specifically, and even with Martian and CR-Bench, the classification of /noise/ should be taken more subjectively than /bug hit/ since /noise/ is unanchored, whereas /bug hits/ and /validity/ are anchored to golden comments provided by the dataset.

Results are from three models.  Configuration for each run:

|-----------+------------------+----------------------------+-----------+----------------------------+----------------|
| model     | backend          | endpoint                   | streaming | reasoning                  | prompt caching |
|-----------+------------------+----------------------------+-----------+----------------------------+----------------|
| opus-4.8  | Anthropic direct | =/v1/messages=             | on        | adaptive, effort =medium=  | off            |
| glm-5.2   | OpenRouter       | =/api/v1/chat/completions= | on        | unified =:effort "medium"= | off            |
| gpt-5.5   | OpenAI direct    | =/v1/chat/completions=     | off       | none                       | off            |
|-----------+------------------+----------------------------+-----------+----------------------------+----------------|

=gpt-5.5= streaming is off because the endpoint rejects =stream_options.include_usage= and =reasoning_effort= alongside tool calls.  Prompt caching is off everywhere (=gptel-cache= defaults to nil), so token counts are billed at full input rate per round.

Hutch also emits =lgtm= findings (a per-file "I looked, nothing wrong" marker).  They carry no content, so the judge classifies all of them as NOISE.  Tables below exclude them from the finding totals and report the count separately.

- Precision  = distinct goldens hit / total findings (lgtm excluded)

** Broader analysis

Precision, Recall, and F1 are anchored to the golden set. Usefulness and SNR depend on the judge's noise classification, which is unanchored.  Read those as soft signals.  Wall time is indicative only (network variance).

The most interesting bits are rounds and token patterns.  =opus-4.8= converges in roughly a third of the rounds =gpt-5.5= takes (9.9 vs 36.5) at the same ballpark hit count.  =gpt-5.5= regularly hits the =max-rounds= cap (p95 = 79 rounds).  =opus-4.8= burns the most input context by a wide margin (7.4M vs 1.7M for =glm-5.2= and 2.1M for =gpt-5.5=), mostly from the growing conversation Hutch resends each tool-use round.  On output tokens per useful finding, =opus-4.8= looks cheapest (2,985).

Model complementarity is substantial.  Each model independently hits 40-50 distinct goldens, but the union of all three hits =78=, about 55% more than any single model.  Only =18= goldens are hit by all three; =15= are opus-only, =13= glm-only, =6= gpt-only.  Different blindspots.  Hints at Hutch possibly union-ing multi-model results in the future.

As a sidenote, these results put Hutch somewhere around the #16 mark on [[https://codereview.withmartian.com/?mode=offline][Martian's Offline Benchmark leaderboard]], which is competitive for a no-memory, single-shot agent.

*** Contamination?

=gpt-5.5= cutoff is Dec 2025, =opus-4.8= cutoff is Jan 2026, =glm-5.2= cutoff is around Oct 2025.  The date span of the =40= PRs is =2023-02= to =2025-07=, so there are no PRs post-cutoff for any of the three.

Historical splits on the June 2026 baseline runs showed both opus-4.8 and gpt-5.5 doing substantially better on older PRs than newer ones (opus −23.9 pp, gpt-5.5 −11.0 pp around the =2024-11= median PR date), which /seems/ consistent with contamination or memorization but is hard to be sure.

In any case, the point of this benchmark isn't to sit at a leaderboard, but just to validate initial-hesitation real-world usefulness.  The benchmarks also completely elide patch applicability correctness, which is a focus point for Hutch, and can only reliably be done with active ("online") usage.
