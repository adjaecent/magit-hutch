Notes on this table:

- *lgtm findings are excluded from the counts.*  hutch added the =lgtm=
  type after the June baseline runs; it's a review-coverage marker
  ("I looked at this file and nothing was wrong"), not a finding.  Each
  one has empty content, so the judge classifies 100% of them as NOISE
  by construction.  Including them in the fresh runs makes the noise
  count look 10-30× worse than the baselines — artifact, not signal.
  The =lgtm= column shows how many were emitted; the baselines show 0
  because the type didn't exist then.
- *Two hit/g columns:*  =current= judges against today's goldens set
  (132 total); =June= drops the 25 goldens Martian added since the
  baseline runs, giving a 107-golden comparator that aligns with the
  June baselines (108 — close enough; 1 PR shrank by one golden).
  Use the =June= column when comparing fresh vs baseline.

Legend:
- =find=   total findings submitted
- =bugs=   judge-classified BUG_HIT (hit a golden)
- =valid=  judge-classified VALID_SUGGESTION (real but not in golden set)
- =noise=  judge-classified NOISE (wrong/irrelevant/hallucinated)
- =hit/g=  distinct goldens hit / total goldens across all PRs
- =use%=   per-PR usefulness rate = (bugs + valid) / findings
- =SNR=    (bugs + valid) / noise
- =o/use=  output tokens per useful (bug + valid) finding
- =wall/pr= mean wall-clock seconds per PR

** How the fresh runs were produced

Both fresh runs went through the same pipeline:

1. =bb prep= — materialize 40 PR worktrees under =/tmp/hutch-eval-repos/=.
2. =bb run --parallel N --out results-<model>.jsonl= — hutch batched via
   emacs =--batch=, trace per PR via =hutch-trace-dir=, judge via
   =gpt-5.2=, append JSONL.
3. Per-model artifacts moved aside to prevent overwrite:
   - traces/  → traces-glm-5.2/  or  traces-openai_gpt-5.5/
   - logs/    → logs-glm-5.2/    or  logs-openai_gpt-5.5/

Backends:

#+begin_src elisp
;; glm-5.2 — streamed, unified :reasoning (:effort "medium")
(gptel-make-openai "OpenRouter"
  :host "openrouter.ai"
  :endpoint "/api/v1/chat/completions"
  :key (getenv "OPENROUTER_API_KEY")
  :models '(z-ai/glm-5.2)
  :request-params '(:reasoning (:effort "medium")
                    :stream_options (:include_usage t)))

;; gpt-5.5 — non-streamed; the /v1/chat/completions endpoint rejects
;; both reasoning_effort and stream_options.include_usage alongside
;; tool calls, so streaming is off (non-streamed responses always
;; include usage in the final body).  No reasoning is sent.
(gptel-make-openai "OpenAI"
  :key (getenv "OPENAI_API_KEY")
  :models '(gpt-5.5)
  :stream nil)

;; opus-4.8 — Anthropic direct; current API uses the "adaptive" thinking
;; shape (older "enabled" + :budget_tokens is rejected for this model).
;; `:output_config (:effort "medium")` is the dial for how hard it thinks.
(gptel-make-anthropic "Claude"
  :key (getenv "ANTHROPIC_API_KEY")
  :models '(claude-opus-4-8)
  :request-params '(:thinking (:type "adaptive")
                    :output_config (:effort "medium")))
#+end_src

** Caveats worth repeating

- *Input tokens are only present in the fresh runs.*  The June baselines
  were on an older gptel that didn't populate input tokens in the
  callback info plist.  Fixed in [[../hutch.el][hutch.el]] by bumping
  the =gptel= floor to 0.9.9.4 and reading =(plist-get info :tokens)=.
  Any cost comparison vs. the baseline is output-only.

- *Reasoning tokens are folded into output_tokens for reasoning models.*
  OpenAI counts =completion_tokens= as =visible_output + reasoning=.
  GLM via OpenRouter similarly surfaces reasoning in the completion
  side.  The =o/use= column therefore conflates "produce the finding"
  with "think about it."  gpt-5.5 here runs without reasoning (API
  restriction), so its number is reasoning-free; GLM's is not.

- *Noise, once lgtm is filtered, is a non-story.*  Earlier runs of the
  summary showed noise jumping 4 → 121 for opus, 4 → 19 for gpt-5.5.
  That was entirely explained by the =lgtm= finding type (added to hutch
  after the baselines).  Every lgtm has empty content and is auto-noise.
  With lgtm filtered, fresh noise counts are 0-9, in line with the
  baselines' 4-each.  Judge model and judge behavior are unchanged.
- *Model behavior did shift slightly in a different direction.*  Opus
  dropped from 160 substantive findings (June) to 95 (today), and
  gpt-5.5 from 112 to 86.  Model learned to be more selective, lgtm'ing
  files instead of commenting on them.  Distinct bug hits stayed stable
  (opus 50 ≈ 51, gpt-5.5 40 = 40) — fewer things flagged, same real
  issues caught.

- *The golden set grew between runs.*  June: 108 total goldens across 40
  PRs.  Current: 132 goldens.  Martian updated the =golden_comments/*=
  dataset; the fresh runs are judged against the newer, bigger set.
  Interestingly both fresh and baseline gpt-5.5 hit exactly *40* distinct
  goldens — the absolute count is unchanged, only the denominator
  (recall) moved.
